# FAERS Adverse Event Demographics: EDA & Association Rule Mining

Exploratory data analysis and association rule mining on the **FDA Adverse Event Reporting System (FAERS)** demographic files for **Q1 and Q2 of 2025**.

The project cleans and merges two quarterly extracts into one dataset, explores it with 22 visualizations, and then uses the **Apriori algorithm** to find which case attributes (sex, age group, reporter occupation, report type, submission method, country) tend to occur together.

## Project Overview

FAERS is a public database of adverse event and medication error reports submitted to the U.S. FDA. This project focuses on the **DEMO (demographic) table**, which has one row per case version with patient and report details.

**Objectives**

- Combine the Q1 2025 and Q2 2025 DEMO files into a single clean dataset.
- Profile data quality (missing values, implausible ages and weights, duplicates).
- Explore patient demographics and reporting patterns.
- Mine association rules between categorical case attributes using Apriori.
- Export the cleaned dataset for downstream work.

## Dataset

## How to Run

1. Download `demo2025q1` and `demo2025q2` from the FDA FAERS page and save them as CSVs in `data/`.
2. Launch Jupyter:
   ```bash
   jupyter notebook notebooks/faers_eda_association_rules.ipynb
   ```
3. Confirm the file paths in the **Loading the Dataset** cell point to your CSVs.
4. Run all cells (**Kernel > Restart & Run All**).
5. The merged dataset is written to `faers_2025_demo_merged.csv.gz`.

## Methodology

**1. Data cleaning**
- Verified both quarters share an identical column schema.
- Added a `quarter` column (`2025Q1` / `2025Q2`) before merging.
- Converted `event_dt`, `mfr_dt`, `init_fda_dt`, `fda_dt`, `rept_dt` from `YYYYMMDD` to datetime (invalid values become `NaT`).
- Trimmed whitespace in categorical columns and converted blanks, `'nan'` and `'UNK'` to missing.
- Set age outside 0 to 122 and weight outside 0 to 400 to missing.

**2. Merging**
- Concatenated Q1 and Q2 and dropped duplicates on (`primaryid`, `caseid`, `caseversion`).
- Converted categorical columns to the `category` dtype to save memory.

**3. Exploratory analysis**
22 charts covering case volume, demographics, report characteristics, geography, time trends, correlations and cross-tabulations, plus summary statistics.

**4. Association rule mining**
- Each case becomes a "basket" of `column=value` items, for example `{sex=F, age_grp=A, occp_cod=MD, rept_cod=EXP, e_sub=Y}`.
- Basket columns: `sex`, `age_grp`, `occp_cod`, `rept_cod`, `e_sub`, `wt_cod`, `i_f_code`, `reporter_country` (top 9 countries plus `OTHER`).
- Cases missing more than 3 of the 8 attributes are dropped.
- A random sample of **60,000** cases (`random_state=42`) is used for speed.
- Apriori runs with `min_support = 0.03`; rules are kept at `lift >= 1.1`.

## Association Rule Metrics

| Metric | Meaning | Reading it |
|---|---|---|
| Support | Share of cases containing the itemset | Higher = more common |
| Confidence | P(consequent given antecedent) | Higher = more reliable rule |
| Lift | Confidence relative to chance | > 1 positive, 1 independent, < 1 negative |
| Leverage | Observed minus expected co-occurrence | 0 = independent |
| Conviction | How strongly the antecedent implies the consequent | Higher = stronger implication |
| Zhang's metric | Normalized association in [-1, 1] | Closer to 1 = strong positive |

## Key Findings

*Add your actual numbers here after running the notebook. The saved notebook does not include cell outputs, so the points below are the qualitative conclusions from the notebook's own summary.*

- The two quarterly extracts held roughly 400K and 393K raw rows before cleaning and de-duplication.
- The typical FAERS reporter profile is majority-female, adult-to-elderly, US-dominated, mostly electronically submitted, and largely filed as Expedited (EXP) or Periodic (PER) reports.
- Association rules show high-lift links between reporter occupation, report type and submission method.

## Limitations

- **Reporting bias:** FAERS is a voluntary and mandatory spontaneous reporting system, so it cannot be used to estimate incidence or prove causation.
- **Association is not causation:** the rules describe co-occurrence of report attributes, not clinical relationships.
- **Sampling:** rule mining uses a 60,000-case sample, so results can shift slightly with a different seed.
- **Demographic table only:** drug (`DRUG`) and reaction (`REAC`) tables are not used.
- **Missing data:** several fields (weight, occupation, manufacturer fields) are sparse.
